# Implementation Notes

이 문서는 Undead Survivor의 주요 구현 방식과 개선 가능성을 정리한 문서입니다.

## 1. Object Pooling

적과 투사체는 게임 중 반복적으로 생성되고 사라지는 오브젝트입니다.  
매번 `Instantiate`와 `Destroy`를 반복하면 런타임 비용이 커질 수 있기 때문에 `PoolManager`를 사용해 비활성 오브젝트를 재사용하도록 구성했습니다.

현재 구조는 프리팹 배열의 인덱스를 기준으로 풀을 관리합니다.

### 현재 장점

- 적과 투사체의 반복 생성 비용을 줄일 수 있습니다.
- 비활성화된 오브젝트를 다시 활성화하는 방식으로 재사용합니다.
- 구현이 단순해서 소규모 프로젝트에 적용하기 쉽습니다.

### 개선 가능성

- 초기 생성 개수 설정
- 최대 생성 개수 제한
- 프리팹 이름 또는 enum 기반 조회
- 풀 상태를 확인할 수 있는 디버깅 정보 추가

## 2. Auto Combat

모바일 환경에서는 이동과 공격을 동시에 직접 조작하기 어렵기 때문에 공격은 자동화했습니다.

`Scanner`가 주변 적 중 가장 가까운 대상을 찾고, `Weapon`이 현재 무기 타입에 맞춰 근접 공격 또는 원거리 공격을 실행합니다.  
`Bullet`은 피해량, 관통 횟수, 충돌 후 비활성화 흐름을 담당합니다.

### 현재 장점

- 플레이어는 이동에 집중할 수 있습니다.
- 가장 가까운 적을 기준으로 공격 대상을 자동 선택합니다.
- 근접 무기와 원거리 무기를 하나의 무기 흐름에서 처리할 수 있습니다.

### 개선 가능성

- 공격 우선순위 조건 추가
- 보스, 일반 적, 체력 낮은 적 등 타겟팅 기준 다양화
- 무기별 사거리와 공격 방식 세분화

## 3. Enemy Spawn

`Spawner`는 게임 진행 시간에 따라 `SpawnData`를 선택하고 적을 생성합니다.  
`SpawnData`에는 스폰 주기, 적 종류, 체력, 이동 속도 정보가 포함됩니다.

### 현재 장점

- 진행 시간 기준으로 난이도 흐름을 만들 수 있습니다.
- 스폰 데이터를 수정해 적의 등장 패턴을 조정할 수 있습니다.
- 스폰된 적은 오브젝트 풀을 통해 재사용됩니다.

### 개선 가능성

- 웨이브 단위 스폰 추가
- 보스 등장 시간 지정
- 맵 위치별 스폰 확률 조정
- 난이도별 스폰 데이터 분리

## 4. Game State

`GameManager`는 게임 시작, 진행 시간, 체력, 레벨, 경험치, 생존 성공, 사망, 결과 화면 전환을 관리합니다.

### 현재 장점

- 게임 전체 흐름을 한 곳에서 파악할 수 있습니다.
- 시작, 정지, 재개, 재시도 흐름이 단순합니다.
- UI와 사운드 전환을 게임 상태에 맞춰 처리할 수 있습니다.

### 개선 가능성

현재는 `GameManager`에 많은 책임이 집중되어 있습니다.  
프로젝트 규모가 커질 경우 다음과 같이 역할을 분리할 수 있습니다.

- `GameStateManager`: 시작, 진행, 정지, 종료 상태 관리
- `PlayerStats`: 체력, 경험치, 레벨 관리
- `ResultController`: 결과 화면 전환 관리
- `SoundController`: 게임 상태에 따른 사운드 호출 관리

## 5. Player Damage

현재 플레이어는 적과 충돌 중일 때 지속적으로 체력이 감소합니다.  
체력이 0 이하가 되면 플레이어 사망 애니메이션과 게임 오버 흐름으로 전환됩니다.

### 현재 장점

- 충돌 기반 피해 처리가 단순합니다.
- 생존형 게임의 압박감을 쉽게 표현할 수 있습니다.

### 개선 가능성

- 피격 쿨타임 추가
- 무적 시간 추가
- 적 종류별 공격력 분리
- 피해량을 하드코딩하지 않고 데이터로 관리

## 6. Level Up

레벨업 시 `LevelUp`이 보상 후보를 표시하고, 선택된 아이템은 무기 또는 장비 성장 효과로 연결됩니다.

### 현재 장점

- 경험치 획득과 성장 선택 흐름이 연결되어 있습니다.
- 보상 선택 중 게임을 멈춰 사용자가 선택에 집중할 수 있습니다.
- `ItemData`를 통해 아이템 정보를 데이터 형태로 관리할 수 있습니다.

### 개선 가능성

- 아이템 등급 추가
- 중복 선택 제한 규칙 추가
- 무기 조합 또는 진화 시스템 추가
- 보상 후보 등장 확률 조정

## 7. UI and Result Flow

`HUD`는 플레이 중 필요한 정보를 갱신하고, `Result`는 생존 성공 또는 사망 결과를 표시합니다.

### 현재 장점

- 플레이 상태와 결과 상태가 화면으로 구분됩니다.
- 경험치, 레벨, 처치 수, 시간, 체력 정보를 HUD로 확인할 수 있습니다.

### 개선 가능성

- 결과 화면에 플레이 통계 추가
- 최고 기록 저장
- 캐릭터별 기록 분리
- 모바일 화면 비율별 UI 보정

## 8. Summary

Undead Survivor는 모바일 생존형 액션 게임의 기본 플레이 루프를 구현한 실습 프로젝트입니다.

핵심 구현은 다음 흐름으로 구성됩니다.

1. 캐릭터 선택
2. 게임 시작
3. 플레이어 이동
4. 적 스폰
5. 자동 공격
6. 경험치 획득
7. 레벨업 보상 선택
8. 생존 성공 또는 사망
9. 결과 화면 출력

현재 구조는 소규모 실습 프로젝트에 맞게 단순하게 구성되어 있으며, 향후 프로젝트 규모가 커질 경우 상태 관리, 데이터 관리, UI 전환 책임을 분리하는 방향으로 개선할 수 있습니다.
